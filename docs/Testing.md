# Тестирование

В проекте используется многоуровневая стратегия тестирования: автоматизированные **Unit**, *
*Component**, **UI(E2E)** тесты, а также **ручное тестирование** ключевых пользовательских
сценариев.

## Типы тестов

### 1. UI (E2E) тесты

Проверяют работу приложения «глазами пользователя».  
Покрывают ключевые пользовательские сценарии:

- выбор города и веса
- получение списка тарифов
- выбор тарифа
- оформление заказа

**Цель:** проверить весь путь пользователя и работу всей системы в комплексе.

---

### 2. Компонентные тесты

Проверяют отдельные UI-компоненты в изоляции:

- карточки предложений,
- элементы ввода,
- списки тарифов,
- метки real/restored.

**Цель:** убедиться, что UI корректно отображает данные и реагирует на действия.

---

### 3. Модульные (Unit) тесты

Проверяют отдельные функции и бизнес-логику:

- расчёт стоимости,
- обработка веса,
- восстановление пропущенных данных,
- сортировка,
- выбор лучшего предложения.

**Цель:** быстро и надёжно валидировать ядро бизнес-логики.

---

### 4. Ручное тестирование

Ручные тесты используются для проверки:

- полноценного пользовательского пути,
- нового функционала до появления автотестов,
- UX сценариев,
- нефункционального поведения (анимации, восприятие данных).

Основной ручной тест — **Happy Path**, покрывающий успешный сценарий:  
выбор города → ввод веса → получение вариантов доставки → выбор лучшего → оформление заказа.

**Ссылка на хеппик: [HappyPath.md](../testing/HappyPath.md)**

## Пирамида тестирования

     ▲
     │     UI (E2E) тесты
     │     — небольшое количество, самые дорогие
     │
     │───────────────
     │  Компонентные тесты
     │     — стабильные и средние по стоимости
     │
     │───────────────────────────
     │ Unit-тесты
     │     — основа покрытия, быстрые и дешёвые
     │
     │───────────────────────────
     │ Ручное тестирование
     │     — для ключевых сценариев и UX
     ▼

## 🎯 Итог

Комбинация автоматизированных и ручных тестов обеспечивает:

- высокое качество продукта,
- быстрое нахождение логических ошибок,
- проверку визуальных и UX элементов,
- надёжность пользовательских сценариев.

Такой подход снижает количество регрессий и ускоряет релизы.
